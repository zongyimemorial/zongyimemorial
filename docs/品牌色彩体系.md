# 宗忆堂品牌色彩体系（墨金）

> 一句话：**全站色彩从 LOGO 里长出来，不是另挑一套"好看的配色"。**
> 验收 `scripts/verify-brand-palette.mjs`（59 项，含 3 组反向验证）。

---

## 一、为什么要改

改前的品牌色是**冷调蓝灰**（`brand-500 #5b6b7b`、`brand-900 #1f262e`），
而 LOGO 是**深墨金**（暗橄榄褐底 + 立体鎏金浮雕）。两者理念相悖：

| | 改前 | LOGO 实际采样 |
|---|---|---|
| 主色 | `#5b6b7b` 蓝灰 | — |
| 最深色 | `#1f262e` 近黑蓝 | — |
| 底色 | — | `#3a2f18` / `#221709` 暗橄榄褐 |
| 高光 | — | `#e8c56d` 香槟金 → `#fdfcc4` 米金 |
| 辅助 | `#a8744f` 赭石 | `#a9884f` 金棕 |

所以本次不是"挑一套新配色"，而是**把 LOGO 的两个主色直接变成色阶的锚点**：

- `brand-800` = `#3a2f18` ← LOGO 底色，**ΔE = 0.00**
- `accent-300` = `#e8c56d` ← LOGO 金高光，**ΔE = 0.00**

顺带修掉一个**静默的历史缺陷**：`tailwind.config.ts` 原先只定义了
`brand-50/100/500/600/700/800/900`，**没有 `brand-200/300/400`** ——
但代码里有 **233 处 `brand-400` + 44 处 `brand-300` + 12 处 `brand-200`**。
Tailwind 找不到色值就不生成这些类，所以它们**此前全是空样式**（不报错、不警告）。
本次补齐，等于白捡一批修好的视觉。

## 二、⚠️ 三条硬约束（改色值前必读）

这三条都是"违反了不会报错，只会静默变丑"的类型，所以写进断言也写进这里。

### ① 色阶双角色：`brand` 既是文字色又是深底色

| 角色 | 档位 | 用量 | 约束 |
|---|---|---|---|
| **白底上的正文/次要文字** | `brand-400` `brand-500` | 233 + 200 | 必须**够深** |
| **深底（白字压其上）** | `brand-700/800/900` | 341+159+287 | 必须**够深** |
| 浅底/描边 | `brand-50`–`brand-300` | 81+37+12+44 | 明度递增 |

**推论：香槟金绝不能进 `brand-*`。**
一旦把 `brand-400` 变成亮金色，全站 433 处正文会瞬间变成「浅字压白底」。
金色只存在于 `accent-*`，做**装饰**（描边、渐变、图标）。

### ② `accent` 也双角色：叫"金"但一半是文字

`accent-500/600` 有 **164 处文字用法**（`text-accent-600` 143 处 / `text-accent-500` 21 处）。
所以色阶里的"金"必须呈现为**深金 / 古铜金**：

- `accent-500` `#8f6f18` → 4.71:1 ✅
- `accent-600` `#7d5f14` → 5.97:1 ✅

而**亮香槟金 `#e8c56d` 落在 `accent-300`**，专供描边/渐变/图标。
**别把 500/600 往上提亮** —— 那是全站 164 处文字的对比度。

### ③ 暖灰不撞车：`gray` 浅档与 `brand` 浅档要"同族但可辨"

Tailwind 默认灰**偏冷发蓝**，与墨金暖调打架（549 处）。本次覆盖为暖灰。
但两套浅色不能糊成一片：

- ΔE(gray-100, brand-100) = **2.39** ← 落在 [1.5, 6]：同族、看得出差别
- ΔE(gray-300, brand-300) = **13.26** ← 落在 [6, 40]：描边不糊

太小 → 卡片边框与背景糊成一片；太大 → 冷调又回来了。

## 四、首页五大板块卡片

### 设计逻辑

五张卡**共用同一骨架**，只靠一个专属主色区分板块 ——
放在一起是"一套体系里的五个分支"，而不是五张各画各的卡。

```
┌─────────────────────────────┐
│ ▓▓ 顶部 2px 渐变条（专属主色） │
│  ◈  图标（1.5px 线性描边）     │
│     数字纪念馆                │
│     为逝者建立可永久访问…      │
│                    进入 →    │
└─────────────────────────────┘
   底：white → brand-50 极浅暖白渐变
   边：1px brand-200；hover 描金边（accent-400）+ 轻浮起
```

### 五个专属主色

| 板块 | 色相 | 色值 | 意象 | 压卡片底 `#f2ede4` |
|---|---|---|---|---|
| 数字纪念馆 | 青 | `#4d7168` | 青砖碑刻 | 4.64:1 |
| 宗亲文化 | 朱 | `#a0473a` | 宗祠朱漆 | 5.21:1 |
| 云直播 | 赤 | `#a55710` | 灯火流媒 | 4.54:1 |
| 新闻资讯 | 靛 | `#445872` | 典籍墨青 | 6.24:1 |
| 虚拟祭品 | 檀 | `#856432` | 檀木供桌 | 4.66:1 |

**L\* 跨度 8.6**（36.8–45.4）→ 色相拉开但明度齐平，有区分又不刺眼。

> ⚠️ **调色时别只看"压白底"。** 卡片底是暖白（渐变末端 `brand-100 #f2ede4`）而非纯白，
> 要求更严。第一版 `live=#ad5d12` 压白底 4.83:1 看着没问题，压卡片底只有 4.14:1，验收紧在 §6 抓出。
> 所以验收脚本对五个主色**按卡片底色而非白底**判 ≥4.5。

### 实现要点

主色走**内联 CSS 变量**（`--tone` / `--tone-soft`），不写 5 套 Tailwind class：

```tsx
style={{ "--tone": toneColor, "--tone-soft": `color-mix(in srgb, ${toneColor} 12%, #ffffff)` }}
```

`feature-tone-memorial` 这类**动态拼出来的类名 Tailwind 静态提取不到**，
构建后是空样式 —— 本仓库踩过（见 AGENTS.md 的"色阶双角色"）。

图标在 `components/site/FeatureIcons.tsx`，5 枚**内联 SVG**（零外部图标库）：
统一 `viewBox 0 0 24 24` / `stroke="currentColor"` / `strokeWidth={1.5}` / `fill="none"`，
由外层 `color` 着色。所以五个组件共一套画法，只靠色相区分。

## 五、什么"不改"

`lib/hall-decor.ts`（38 行旧 hex）、`lib/decor-3d.ts`、`lib/decor-skin.ts`、
`lib/decor-suites.ts`、`components/clan/arch/palette.ts`、
`components/hall/HallDecorLayer.tsx`、`components/decor/DecorPagePreview.tsx`
里的旧色值 —— 这些是**装修素材自带的设计色**：

- "素线框"的边框色 `#2c3540`
- "赭石"梁柱三色 `#b98559/#a8744f/#8f5f3d`
- 各套件预览底的冷暖配比

它们是**内容**不是**品牌**。跟着换会让**老用户已购素材的外观漂移**
（花 150 积分买的"素线框"一夜之间变了个颜色）。

**判据：`lib/decor-*`、`lib/hall-decor.ts`、`components/decor/*`、
`components/clan/arch/*` 一律不动。**

## 六、验收（`scripts/verify-brand-palette.mjs`）

| § | 内容 | 要点 |
|---|---|---|
| §1 | 配置契约 | brand 10 档 / accent 9 档 / gray 10 档齐全且为合法 hex；brand-200/300/400 已补齐 |
| §2 | 单调性 | 三组色阶亮度**严格递减**（防手滑写反某档） |
| §3 | WCAG 对比度 | 9 条文字色 + 3 条白字压深底 + 2 条金字压暗底 |
| §3c | 暖底上的文字 | 卡片内文字压 `brand-50/100` 也要 ≥4.5（**不只看白底**） |
| §4 | LOGO 同源 | `brand-800` / `accent-300` 与 LOGO 采样 ΔE < 6 |
| §5 | 暖灰不撞车 | ΔE 区间断言（同族但可辨） |
| §6 | 行为层 | 五卡 tone 两两不同、`--tone` 互异且与设计色板相符、渐变条、图标着色、hover 变边 |
| §7 | 反向验证 | 三处注入缺陷，断言**必须真的变红** |
| §8 | 旧蓝灰残留 | 品牌层零残留（装修素材的保留项只打印清单） |

### 三组反向验证（都做了"对照组"）

| 实验 | 期望 | 实测 |
|---|---|---|
| ① `brand-500` 改浅至 `#cfc6b4` | 对比度断言变红 | 1.69:1 < 4.5 → **判红 ✅**；对照组正确值 5.39:1 仍绿 |
| ② 两卡 tone 改成同值 | 「两两不同」变红 | 4 个唯一值 ≠ 5 → **判红 ✅**；对照组 5 个仍绿 |
| ③ `brand-300` 写成 `brand-50` 的值 | 单调性变红 | 逆序于 200→300 → **判红 ✅**；对照组仍严格递减 |

> **反向验证的判据不是"断言红了"，而是"缺陷版与正确版的输出真的不同"。**
> 只注释掉分支、两边算出一样的结果，断言照样绿 —— 那是白测（AGENTS.md 阶段 5 记过）。

### 已知的两个断言陷阱（写在脚本里）

1. **`grep` 输出是 `路径:行号:内容`，内容里也可能含过滤关键词。**
   第一版按整行 substring 判定"是不是装修文件"，把 `components/decor/DecorPagePreview.tsx`
   （路径在品牌层、内容里有 `#1f262e`）误判成装修文件 → 假绿。
   修法：**只取冒号前的路径段**判定归属。
2. **对比度断言不能只验"压白底"。** 卡片底是暖白渐变，比纯白严。
   见 §3c 与 §6 的按卡片底色判定。

### 全量回归

`bash scripts/run-all-verify.sh` —— 40 套既有验收必须全绿。
本次**类名一字未改、只换色值**，所以既有断言理应不受影响；
若变红说明某处把颜色写进了断言，需逐条甄别是**真回归**还是**断言耦合了色值**。
