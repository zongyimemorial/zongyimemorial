# 午夜悄悄话 · 合规框架落地说明

> 配套代码：`lib/whisper-safety.ts`、`lib/whisper-mood.ts`、`app/admin/review/actions.ts`、`app/console/whispers/[id]/actions.ts`
> 配套验收：`scripts/verify-whisper-{compliance,ethics,delete,mood,history}.mts`
> 定位：本文说明「纯语音对话系统」在代码层面如何兑现法律合规要求，供法务复核与后续审计。

---

## 0. 结论先行：产品形态决策

按《"午夜悄悄话"纯语音对话系统规划设计方案》，本产品**明确不做数字人形象**，只保留语音内核。

| 决策 | 内容 | 代码体现 |
|---|---|---|
| 删除数字人 | 移除 `WhisperAvatar` 表、`WhisperProfile.avatarId`、`AvatarPicker` 组件、形象积分项 | 迁移 `20261010000000_whisper_pure_voice` |
| 保留 `mode` 字段 | 值恒为 `voice`，作为未来扩展预留位 | schema 注释标"预留" |
| 历史数据归一 | 历史 `avatar` 模式值统一回落 `voice` | 迁移内 `UPDATE` 语句 |

**为什么删**：实时口型驱动的数字人视频成本是纯语音的 **15–120 倍**，且形象越逼真、「把人当成真的」的心理风险越高。在逝者场景下，这属于深度合成高风险用途。声音已足够唤起怀念，而一张会动的脸更容易让人误以为 TA 回来了。

## 1. 授权链（不可跳过）

**法律依据**：《民法典》第 994 条（死者人格利益）、第 1019 条（声音权参照肖像权保护）；最高法 2026-09-07《关于依法审理涉人工智能纠纷案件的意见》。

| 要求 | 实现 |
|---|---|
| 近亲属**单独**同意 | `WhisperConsent.applicantName` + `relation` |
| 其他近亲属无异议 | `WhisperConsent.otherHeirsAck`（未勾选无法提交） |
| 身份证号加密 | AES-256，密钥由 `AUTH_SECRET` 派生（`lib/crypto.ts`） |
| 可随时撤回 | `revokeConsent` → 置 `revokedAt` 并**立即关闭装置** |
| 无授权不可上线 | `reviewWhisper` 中授权闸门：缺失即强制驳回，即使管理员点「通过」 |

**三重开启闸门**（`toggleEnabled`）：
1. `status === "active"`（已通过人工审核）
2. 存在未撤回的家属授权
3. 已生成人格提示词

关闭则无任何限制——家属可随时停用。

## 2. 伦理审查（新增）

**问题**：声音克隆是对逝者生物特征的复刻，风险等级高于使用平台预设声线。仅靠「审核一次」不足以覆盖。

**方案**：为涉及克隆的装置增加**独立子流程**——伦理审查。纯语音预设声线**不触发**该闸门，避免误伤。

### 数据字段（`WhisperProfile`）

| 字段 | 类型 | 说明 |
|---|---|---|
| `ethicsStatus` | `String` | `not_required`（默认）/ `pending` / `approved` / `rejected` |
| `ethicsReviewer` | `String?` | 审核人 |
| `ethicsReviewedAt` | `DateTime?` | 审核时间 |
| `ethicsNote` | `Text?` | 审查意见 |

### 判定逻辑（`reviewWhisper`）

```
hasClone      = profile._count.voices > 0
ethicsOk      = profile.ethicsStatus === "approved"
ethicsBlocked = hasClone && !ethicsOk

若点「通过」且 (无授权 || ethicsBlocked) → 强制驳回
  · 无授权 → 原因「缺少有效家属授权，系统自动驳回」
  · 伦理未过 → 原因「声音克隆装置未通过伦理审查，系统自动驳回」

若 hasClone 且 ethicsStatus === "not_required" → 自动转 "pending"（进入待审队列）
```

### 伦理审查动作（`reviewWhisperEthics`）

审查要点（写入审核页提示）：
- 样本来源合法（逝者生前录音，非公开渠道抓取）
- 已取得近亲属**单独**同意，其他近亲属无异议
- 逝者生前**无明确反对**表示
- 用途仅限家庭追思，不用于商业或对外传播

**关键约束**：伦理审查**不通过**时，已上线装置被**立即下线**（`enabled: false` + `status: "rejected"`）。

## 3. AI 双标识（《标识办法》）

| 类型 | 载体 | 说明 |
|---|---|---|
| **显式** | `AiBadge` 组件 + `AI_DISCLOSURE` 告知条 | 用户可见的「AI 生成」徽标，对话页顶部固定告知条 |
| **隐式** | `WhisperMessage.aiLabel` + `WhisperProfile.engineLabel` | 元数据溯源，格式 `AI 生成 · <engine> · <ISO 时间>` |

`engineLabel` 由 `currentEngineLabel()` 生成，形如 `deepseek-chat-llm+volcano-asr+volcano-tts`；Mock 模式下为 `mock-llm+mock-asr+mock-tts`。

## 4. 内容安全与危机干预

### 输入侧（`screenUserInput`）

| 命中类型 | 处理 |
|---|---|
| 自杀/自伤倾向 | 返回固定 `CRISIS_REPLY`，含 **12356** 热线，**放下角色**，**不消耗配额** |
| 贬损逝者 | 返回中立文案，不以逝者口吻回应 |
| 迷信求助（求财/求签） | 温和纠偏 |
| 沉浸信号（不出门/只依赖它） | 附 `IMMERSION_NOTE` 现实锚点 |

### 输出侧（`sanitizeAssistantOutput`）

抓出「我回来了 / 我复活了」类表述，**不删句**而是在末尾补澄清，保持语流自然。

### 沉浸防护

- 单次会话软上限 `SESSION_SOFT_LIMIT_MINS = 45` 分钟
- 到点插入温和提示：「想念一个人不必一次说完，随时都可以再来坐坐」
- 禁止诱导长时间停留

## 5. 数据删除权（新增）

**法律依据**：《个人信息保护法》第 47 条。

### 入口

控制台 → 装置管理页底部「删除追思装置」（`DangerZone` 组件）

### 删除范围（级联）

| 对象 | 方式 |
|---|---|
| `WhisperProfile` 本体 | 显式删除 |
| `WhisperVoice`（声线）+ 样本音频 | 外键 `onDelete: Cascade` |
| `WhisperConsent`（授权记录，含加密身份证号） | 同上 |
| `WhisperSession` + `WhisperMessage`（全部对话） | 经 Session 级联 |
| 磁盘 `public/uploads/whispers/<profileId>/` 整棵目录 | `removeWhisperProfileDir()` |

### 安全设计

- **二次确认**：要求输入装置名称（不做浏览器 `confirm`，因为不可测、易被忽略）
- **越权防护**：服务端以 `ownerUserId` 为准，非本人返回「无权删除」
- **审计留痕**：删除**前**写 `AuditLog`（`whisper_delete:<name>`）——删库后 profileId 就不存在了
- **路径穿越防护**：`profileId` 必须匹配 `^[a-z0-9-]+$`（cuid 形态），且规范化后须仍在 `whispers/` 之下

## 6. 情感状态标记（新增）

**为什么**：让「察觉情绪、避免诱导依赖」从被动检测变成主动承接。

### 六档心情（`lib/whisper-mood.ts`）

| key | 标签 | 注入对话层的语境 | 关切 |
|---|---|---|---|
| `calm` | 平静 | 温和日常，不必刻意安慰 | |
| `missing` | 想念 | 多说过去共同经历的具体细节 | |
| `grief` | 难过 | 语气放轻，先承接情绪 | ✓ |
| `guilty` | 自责 | 宽厚回应，不否定这种感受 | ✓ |
| `joyous` | 有喜事 | 语气轻快，多回应细节 | |
| `blank` | 说不上来 | 温和地开个头 | |

### 实现要点

- 选心情在**进对话前**（`WhisperChat` 顶部），**可跳过、可改选**
- 注入位：`composeSparkPrompt(profile, query, mood)` → 追加 `【来访者此刻的心情】<hint>`
- 落库口径：**新建会话时写入**；已有会话仅在原值为空时**补记一次**（不覆盖首记，避免污染回顾统计）
- API 侧白名单校验：非法值静默丢弃，不打断对话

### 回顾页的情绪聚合（`/whispers/[hallId]/history`）

- 统计各心情出现次数（`moodTrend`，按次数降序）
- 若关切情绪（grief/guilty）累计 **≥3 次** → 显示温和求助提示（含 12356）
- **不展示任何比率数字**，不做诊断、不贴标签

## 7. 对话回顾权限口径

**决策：仅会话本人可见。** 即便装置主人也看不到其他来访者的对话。

理由：追思对话属敏感个人信息，最小可见范围是唯一稳妥解。馆主能看的是**聚合统计**（`profileStats`：会话数、消息数、总时长），不是原文。

实现：`listSessions` / `loadSession` 均按 `(profileId, userId)` 双重/三重过滤；越权时 `loadSession` 返回 `null`，页面落到 `notFound()`——**不区分「不存在」与「无权限」**，避免探测。

## 8. 引擎降级策略

`lib/ai/index.ts` 的底线：**绝不因为缺密钥而让整条链路不可用**。

| 层 | 有密钥 | 无密钥 |
|---|---|---|
| LLM | `DEEPSEEK_API_KEY` → DeepSeek | Mock |
| ASR / TTS | `VOLCANO_APP_ID` + `VOLCANO_ACCESS_TOKEN` → 火山 | Mock |
| TTS（可选） | `COSYVOICE_ENDPOINT` 自建优先 | — |

任何 provider 抛错 → `safeTranscribe` / `safeSynthesize` 捕获并回退 Mock（用户永远拿得到回复，而不是 500）。

**审核页可见性**：`/admin/review` 顶部展示当前引擎标识与模式，避免把演示回复当成线上效果来判断质量。

## 9. 留痕要求

| 项 | 要求 | 实现 |
|---|---|---|
| 对话日志 | ≥ 6 个月 | `LOG_RETENTION_MONTHS = 12` |
| 审核动作 | 可追溯 | `AuditLog`：`whisper_active` / `whisper_rejected` / `whisper_ethics_*` / `whisper_delete` |
| 样本留存 | 可申请删除 | `SAMPLE_RETENTION_NOTE` 在管理台告知；`deleteVoice` 删样本文件而保留声线 |
