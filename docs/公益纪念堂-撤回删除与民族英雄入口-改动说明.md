# 公益纪念堂 · 申请人撤回/删除 与 民族英雄入口 改动说明

> 关联提交：`bb02b09`（`feat(memorial): 公益纪念堂申请人/管理员撤回与删除`），已推送至 `main`。
> 适用范围：公益纪念堂（`/memorial`）板块。

---

## 一、需求背景

公益纪念堂由逝者近亲属（家属/近亲属）免登录提交申请，平台审核通过后免费建堂并公开展示。
原流程缺少「申请人自主撤回或删除」以及「平台管理员下架或删除」的能力，存在两类诉求：

1. **申请人侧**：家属提交后想撤回申请，或纪念堂上线后想撤下/删除（例如信息有误、家属反悔、隐私顾虑）。
2. **平台侧**：管理员在审核台需能下架（临时）或删除（永久）申请与纪念堂，用于合规处置。

## 二、功能概览

| 角色 | 撤回（软操作） | 删除（硬删除） |
|---|---|---|
| **申请人**（免登录，凭管理凭证链接） | 审核中可「撤回申请」（移出审核队列）；上线后可「撤下纪念堂」（`TAKEN_DOWN`，保留记录、公开页变 404，可日后恢复） | 「永久删除纪念堂与申请」：事务内级联删除纪念堂及其全部留言/花圈/祭品 + 申请记录，**不可恢复** |
| **平台管理员**（后台 `/admin/memorial-review`） | 已上线纪念堂「下架」（置 `TAKEN_DOWN`） | 待审申请「删除」；已上线/已下架纪念堂「永久删除」（事务内级联） |

**语义约定**
- **撤回** = 软操作：申请删除记录 / 纪念堂置 `TAKEN_DOWN` 保留数据；
- **删除** = 硬删除：`$transaction` 内解引用 + 级联删除 memorial + 删除 application，并写入审计日志。

## 三、申请人识别方案：管理凭证链接（免登录）

申请表单为免登录提交（申请记录无 `userId`），因此采用**凭证链接**方案：

- 提交申请时生成 48 位随机 `manageToken`（`randomBytes(24).toString("hex")`，不可猜测），存入申请记录（`String? @unique`）。
- 申请成功页展示**私有管理链接**：`/memorial/apply/manage?token=<token>`，并提示用户妥善保存。
- 凭该链接即可免登录进入「我的公益纪念堂管理」页，按当前状态展示对应操作入口，无需注册/登录。

> 凭证即权限：链接一旦用于撤回/删除导致记录消失，该凭证随之失效（再次访问提示「管理凭证无效或已失效」）。

## 四、数据模型变更

`PublicMemorialApplication` 模型新增字段：

```prisma

```

## 六、使用流程

**申请人**
1. 提交申请 → 成功页复制管理凭证链接；
2. 打开链接 → 按状态看到：审核中「撤回申请」/ 上线「撤下纪念堂」「永久删除」/ 驳回或已下架「彻底删除记录」；
3. 每次破坏性操作均弹窗二次确认。

**管理员（后台审核台）**
1. 待审申请卡片 → 「删除」；
2. 已上线卡片 → 「下架」旁「删除（永久）」；
3. 「已下架纪念堂」区块 → 永久删除入口。

## 七、安全与审计

- 所有删除/撤下动作写入复用表 `prisma.auditLog`（`action` / `entity` / `entityId`），**不记录 token**；
- 申请人动作以 `token` 鉴权，无登录态；管理员动作沿用 `requireStaff()`（admin/super_admin）守卫；
- 公开页可见性：纪念堂 `TAKEN_DOWN` 后详情页返回 404，保留后台记录。
