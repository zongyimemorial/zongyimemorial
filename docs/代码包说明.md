# 代码包（git bundle）说明与选择指南

## 1. 背景

本仓库的本地开发环境（沙箱）**出站网络屏蔽了 github.com**，无法直接从这里 `git push`。
为把代码交出去，采用 **git bundle** 作为离线桥接：把完整 Git 历史打包成单个文件，在**任何能连 GitHub 的机器上**克隆后直接推送即可。

仓库当前已就绪：`origin` 指向 `https://github.com/zongyimemorial/zongyimemorial.git`，分支 `main`，共 12 个提交，工作区干净；图片/音频等二进制已由 **Git LFS** 管理（见第 12 节，真实对象随 `zongyimemorial-lfs-objects.tar.gz` 单独交付）。

> ⚠️ 必须先在 GitHub 上创建**空仓库**（不要勾选自动初始化 README/.gitignore），否则首次 push 会因历史不一致被拒。

## 3. 各包详细内容

### 3.1 `zongyimemorial-main.bundle`（完整版，123 MB）
- **适用**：希望 GitHub 仓库与本地完全一致、站点可直接运行（含 `public/` 图片资源）。
- **内容**：12 个提交的全部历史；`app/ lib/ components/ prisma/ scripts/ types/` 源码与配置；`public/` 全部静态资源（hero/商品图/favicon 等，**LFS 指针**）；`docs/` 全部（含 `screenshots`）与 `mobile-shots/` 截图；`.github/` CI 工作流。
- **剔除**：无。`.env` / `.env.bak` 已被 `.gitignore` 排除，不会进包。

### 3.2 `zongyimemorial-code-only.bundle`（去资源版，48 MB）
- **适用**：仓库想保留文档与截图，但**不把 `public/` 大资源入库**（适合后续把图片迁对象存储 / Git LFS）。
- **内容**：同完整版，但**不含 `public/`**。
- **剔除**：`public/` 全部（约 75 MB）。

### 3.3 `zongyimemorial-source-only.bundle`（纯源码版，1.4 MB）
- **适用**：只想最快把**代码**推上 GitHub，资源另行处理；或网络传输受限、需要极小包。
- **内容**：12 个提交；所有源码与配置；`docs/*.md` 文本文档（极小、是交付物，保留）。
- **剔除**：所有图片/二进制资产——`public/`、`docs/screenshots/`、`mobile-shots/`、根目录 PNG 截图、`*.docx` 可行性报告。

## 4. 端到端实操（下载 → 克隆 → 推送 → 收尾）

> 沙箱出站屏蔽 github.com，无法直推。三步走：**从沙箱下载 bundle → 在能连 GitHub 的机器上克隆并推送 → 收尾配置**。

### 4.1 第一步：从沙箱把 bundle 下载到本地

在能访问沙箱 `127.0.0.1:8088` 端口的机器浏览器打开 `http://127.0.0.1:8088/`，下载任一 `.bundle`：

| 选哪个 | 体积 | 适用场景 |
|--------|------|----------|
| `zongyimemorial-source-only.bundle` | 1.4 MB | **推荐**：最快上 GitHub，资源另行处理 |
| `zongyimemorial-code-only.bundle` | 48 MB | 保留文档/截图，但不入库 `public/` |
| `zongyimemorial-main.bundle` | 123 MB | 原样含 `public/` 全部图片 |

> 若无法直连沙箱 8088 端口，改用沙箱的文件下载/导出通道把包取回，再跳到 4.2。

### 4.2 第二步：克隆 bundle 并改远端

把包拷到**能连 github.com 的机器**后：

```bash
# 关键：git bundle 不写 HEAD 符号引用，必须 -b main 显式指定分支
git clone -b main zongyimemorial-source-only.bundle zongyimemorial
cd zongyimemorial

# 把 origin 指向真实 GitHub 仓库
git remote set-url origin https://github.com/zongyimemorial/zongyimemorial.git
```

### 4.3 第三步：推送（按远端仓库状态二选一）

**A. 远端是空仓库**（新建、无任何提交）——直接推：

```bash
git push -u origin main
```

**B. 远端已有初始提交**（如创建仓库时勾了 README）——历史会冲突，二选一：

```bash
# 想保留 GitHub 那边的初始提交：
git pull --rebase origin main
git push -u origin main

# 或想用本地这版干净的 7 提交覆盖（确认你能覆盖再执行）：
git push -u origin main --force
```

### 4.4 第四步：收尾

- 推送成功后，GitHub 自动触发 CI（`ci.yml`：构建门禁 + 验收 + PR 评论）；CI 通过后再由 `deploy.yml` 部署。
- **fork-PR 自动评论功能**依赖仓库密钥 `PR_TOKEN`（带 `pull-requests: write` 的 PAT）。未配置时该步骤失败，但 `build` + `verify` 照常运行，不影响部署门禁。
- 若推送的是 `code-only` / `source-only`，部署前需按第 6 节补齐 `public/` 静态资源，否则页面图片会 404。

---

## 5. ⚠️ git bundle 的 HEAD 怪癖（必读）

`git bundle` **不会**把 `HEAD` 符号引用写入包内。因此：

- ❌ `git clone <包>`（不带分支）→ 报 `remote HEAD refers to nonexistent ref, unable to checkout`，克隆后会落在**游离 HEAD**、没有工作分支。
- ✅ **必须** `git clone -b main <包>` 显式指定分支，才能干净检出并落在 `main` 上。

这是 bundle 传输的已知行为，与包体积/内容无关——三个包都一样，务必带 `-b main`。

---

## 6. 运行时注意（仅对 code-only / source-only）

`public/` 目录被剔除后，克隆出的仓库**缺少站点静态资源**（hero 图、商品图、favicon 等）。直接 `next build && next start` 能编译，但页面图片会 404。

补齐方式（任选其一）：
- 从完整版 `main.bundle` 单独取出 `public/` 拷回；
- 把 `public/` 上传到对象存储/CDN，代码里改为引用 CDN 地址；
- 对 `public/` 启用 **Git LFS**，再单独提交资源。

> `source-only` 连 `docs/screenshots`、`mobile-shots` 都没有，文档里的图片链接也会失效——但代码可正常构建运行。

## 8. 在沙箱内重新生成（可复现）

若需重新打包，在 `/workspace` 所在环境执行（以 source-only 为例）：

```bash
# 纯源码版：克隆副本 → 历史剔除二进制 → 打包
rm -rf /tmp/pure-repo && git clone --no-hardlinks /workspace /tmp/pure-repo
cd /tmp/pure-repo
git filter-branch --force --index-filter '
  git rm -r --cached --ignore-unmatch public mobile-shots docs/screenshots 2>/dev/null
  git ls-files -z | grep -z -iE "\.(png|jpe?g|gif|webp|docx?|ico|heic)$" \
    | xargs -0 -r git rm --cached --ignore-unmatch
' -- --all

# 注意：不要用 --prune-empty。本仓库有"仅修改 docs/代码包说明.md"的提交，
# --prune-empty 会把它误判为空提交而丢弃，导致 source-only 少一提交、缺端到端实操内容。
# 本仓库过滤后无真正为空的提交，去掉该参数即可安全保留全部历史。
git for-each-ref --format='%(refname)' refs/original/ | xargs -n1 git update-ref -d 2>/dev/null || true
git reflog expire --expire=now --all 2>/dev/null || true
git gc --prune=now
git remote remove origin 2>/dev/null || true
git symbolic-ref HEAD refs/heads/main
git bundle create /workspace/zongyimemorial-source-only.bundle main
```

> `code-only` 版只需把上面的 `git rm` 列表改成只删 `public`；`main` 版直接 `git bundle create ... main`（无需 filter-branch）。

## 12. `public/` 资源处理（已实施：Git LFS）

已选定 **Git LFS** 方案并落地：仓库新增 `.gitattributes`（按扩展名追踪图片/音频/字体/文档等二进制），并通过 `git lfs migrate import --everything` 把**全部历史**的二进制转为 LFS 指针（共 **332 个 LFS 对象、约 124 MB**）。仓库本身只存指针文本，克隆轻量；真实对象由 `zongyimemorial-lfs-objects.tar.gz` 单独交付。

> **取舍说明**：当初并列考虑过"对象存储 + CDN"方案，但它需要你自备云存储账号与域名、且要改业务代码里的资源引用前缀，门槛更高；Git LFS 零外部依赖、仓库自带资源、最省事，故选它。若日后图片量超过 GitHub LFS 免费额度（**1 GB 存储 + 1 GB/月 带宽**），再迁 CDN 也不迟。

### 12.1 离线交付物（沙箱 HTTP 服务 `127.0.0.1:8088`）
- `zongyimemorial-main.bundle`（1.4 MB）：完整仓库，`public/` 等为 **LFS 指针**。
- `zongyimemorial-code-only.bundle`（1.4 MB）：剔除 `public/`，其余二进制同为指针。
- `zongyimemorial-source-only.bundle`（1.4 MB）：纯源码、零二进制，可**直接 `git clone`**（无需 skip-smudge）。
- **`zongyimemorial-lfs-objects.tar.gz`（122 MB）**：真实图片/音频对象的压缩包，是 `main`/`code-only` 包的"拼图"——**二者缺一不可还原图片**。

### 12.2 把代码 + 图片推上 GitHub（在能联网的机器上）
```bash
# 1) 克隆主包（必须 skip-smudge，否则会因拉不到真实对象而失败）
GIT_LFS_SKIP_SMUDGE=1 git clone -b main zongyimemorial-main.bundle zongyimemorial
cd zongyimemorial

# 2) 解压真实对象进 .git/lfs/objects（让本机持有图片实体）
mkdir -p .git/lfs/objects
tar -xzf ../zongyimemorial-lfs-objects.tar.gz -C .git/lfs

# 3) 改远端并推送（先传 LFS 对象，再传代码 + 指针）
git remote set-url origin https://github.com/zongyimemorial/zongyimemorial.git
git lfs install
git lfs push --all origin     # 先把 122 MB 真实对象传上 GitHub LFS
git push -u origin main        # 再推代码 + 指针
```
> 推完执行 `git lfs ls-files` 应列出全部资源；GitHub 仓库的 `public/` 即为真实图片。

### 12.3 只想要代码、暂不要图片
直接 `git clone -b main zongyimemorial-source-only.bundle`（无需 skip-smudge），按第 4 节 `set-url → push` 即可；图片后续按需用 12.2 流程补推。

### 12.4 回滚
迁移前已备份：`/tmp/pre-lfs-migrate.bundle`（旧 SHA、含历史原始二进制）。如需撤销 LFS，从它克隆恢复即可（`git lfs migrate export` 亦可，但需本地 LFS 对象完整）。
