# 纪念馆 · 壁龛纪念墙（遗像嵌入实景空间）

> 需求：**「把纪念馆空间中的逝者遗像放到（这张参考图的）中上方。」**
>
> 参考图：木质格状壁龛纪念墙（9 列 × 5 行共 45 格）+ 两侧灰蓝落地窗帘 +
> 左右各一盏金色灯柱 + 墙前长条木柜 + 柜上白色菊花花束（系大蝴蝶结）+
> 灰色大理石地面 + 顶部嵌入式射灯 + 柜外两侧绿植。

## 一、最终决策

| 议题 | 决策 | 理由 |
|---|---|---|
| 图片用途 | **做成新的「整套模板」** `tpl-niche` | 一键应用即得整个空间，而不是只换封面或只换壁纸 |
| 遗像位置 | **壁龛墙正中偏上的格子里** | 即「顶行的正中格」（第 5 列第 1 行），视觉重心在墙面中上方 |
| 实现方式 | **按图重绘成纯 SVG 场景** | 见下 |

### 为什么不用参考图当底图

看似省事，但有三个硬伤：

1. **每换一个馆都是同一张背景** —— 遗像换了，背景不会跟着变；
2. **格位是固定像素**，手机上必然错位；
3. 需要商用授权。

重绘后格位坐标系由代码决定，遗像可用百分比精确嵌入任意格，
且**零外部资源**（与 `lib/hall-decor.ts` 既定的隧道环境约束一致）。

## 二、核心机制：一份几何，两处消费

遗像是 HTML `<img>`，壁龛格画在 SVG 里 —— 两套 DOM 各算各的比例必然错位。
本方案用一条约束把它摁死：

```
NICHE_GRID（百分比几何）
   ├──> NicheWallScene  用它画 45 个壁龛格（SVG）
   └──> nicheCell()     用它把遗像 <img> 绝对定位到同一个格（HTML）
```

`nicheCell(col, row, inset)` 是唯一的换算入口，两处共用一个函数，
所以**不可能**算出两个不同的位置。

### 更难的一层：SVG 的 letterbox 留白

`preserveAspectRatio="xMidYMid meet"` 在非 1200:700 的容器里会**留白**。
若遗像直接按**容器**的百分比定位，一出现留白就会与画出来的格子错开。

解法是把「SVG + 遗像」一起放进一个**保持 1200:700 比例的内层盒子**，
由外层限高容器负责 letterbox 这个盒子。这样内层盒子的坐标系与 SVG 的
`viewBox` **严格同构**，百分比定位永远与画出来的格子对齐 —— 与外面怎么缩放无关。

> 这条已被验收套件在 1440 / 768 / 375 三档下实测锁定
> （三档实测盒子比例均为 `1.714` = 1200/700）。

## 三、几何参数（来自参考图实测）

```ts
export const NICHE_GRID = {
  cols: 9, rows: 5,          // 45 个壁龛格
  left: 15.2, top: 12.4,     // 格区起点（%）
  cellW: 7.35, cellH: 8.9,   // 单格尺寸（%）
  gapX: 0.72, gapY: 1.35,    // 格间距（%）
};

/** 遗像默认落位：顶行的正中格 */
export const NICHE_PORTRAIT_SLOT = { col: 4, row: 0 };
```

9 列的中列是 index 4（左右各 4 列）；5 行取 index 0（顶行）。

## 四、场景构成（`components/hall/NicheWallScene.tsx`）

`viewBox="0 0 1200 700"`，`preserveAspectRatio="xMidYMid meet"`，自包含 SVG。

| 层 | 内容 | 画法要点 |
|---|---|---|
| 背景 | 后墙 + 两侧灰蓝石屏板 | 石屏把木饰面包起来，形成「内凹画框」感 |
| 木饰面 | 底板 + 横向木纹 + 四周内阴影 | 20+ 条 0.8px 木纹线，让木板不是一块纯色 |
| **壁龛格 ×45** | 木框 + 内凹白面板 + 金属铭牌 | **见下（关键）** |
| 顶光 | 筒灯洗墙 + 4 个筒灯本体 | 暖色竖向光晕 |
| 长柜 | 柜体 + 台面挑边 + 4 抽屉 | 台面比柜体略亮并左右挑出一线 |
| 柜面陈列 | 2 盏金灯柱 + 1 束白菊（含纱质蝴蝶结） | 灯柱有玻璃罩、灯芯、六角棱线、提环 |
| 绿植 | 柜外两侧各一盆 | 陶盆 + 12 片长条叶（含叶脉） |
| 地面 | 灰白大理石 | 斜向石纹 + 柜体倒影渐隐 |
| 窗帘 | 最外两侧落地帘 | 6 道褶皱 + 束带收腰 + 内缘投影 |

### 壁龛格：内凹感的三个必要条件

格子必须读成「凹进去的方格」，而不是「贴上去的白纸」。做法：

1. **面板渐变方向必须是「左上暗 → 右下亮」**。
   光从上方筒灯打下来，凹格的上沿被框体挡住形成阴影、下沿受光更亮。
   *反过来（上亮下暗）会读成凸出来的白纸* —— 这是初版踩过的坑。
2. **四面立面用梯形而非矩形**，才能读成「斜切进去的凹格」。
   上/左是背光面（深），下/右是受光面（浅）。
3. **右下角一枚小金属铭牌**（呼应参考图）。

> 遗像叠加时用 `nicheCell(..., inset = 0.18)` 内缩 18%，
> 让木框露出来 —— 读成「放进壁龛里」，而不是「贴了张纸盖住格子」。

## 五、素材与模板

### 不新增槽位

新增 `DecorSlot` 会牵动 `Record<DecorSlot,…>` 的硬编码与纪念馆所有逻辑。
因此改为给 `OrnamentSpec` 增加一个 kind：

```ts
| { kind: "niche-wall"; color: string }
```

`ornament` 槽位本就承载「陈设」语义，壁龛墙正是一整套陈设的底衬，语义成立，
且**完全不影响现有 7 个模板与所有槽位**。

### 遗像为什么不在 `OrnamentSpec` 里

遗像是**业务数据**（`hall.archive.portrait`），不是装修数据。
若塞进 `OrnamentSpec`：

- 会污染装修方案的归一化逻辑（`normalizeDecor` 要处理它）；
- **馆主没上传遗像时无法兜底**（装修方案里写死一个 URL 会 404）。

因此本 kind 只描述「空墙」，遗像由馆页在最外层自行叠加。
`HallDecorLayer.Ornament` 里对该 kind 显式 `return null`，避免重复渲染。

### 新增内容

| 类型 | id | 名称 | 档位 |
|---|---|---|---|
| 挂饰 | `orn-niche-wall` | 壁龛纪念墙 | **free** |
| 模板 | `tpl-niche` | 壁龛纪念堂 | **free** |

模板槽位：`wall-warm` / `floor-marble` / `orn-niche-wall` / `frame-gold` / `font-serif`

> 定档免费的考量：它是「实景感」的门面担当，作为免费模板的门面更能拉新；
> 与项目「普通的免费，精美的收费」既有原则一致。

## 六、遗像缺失时的行为

| 情形 | 行为 |
|---|---|
| 有遗像 | 嵌进正中偏上的壁龛格，套 `frame` 槽位的相框（`box-sizing: border-box`，不撑破格子） |
| 无遗像 · 访客 | **该格保持空白**（与其它 44 个空格一致），绝不画破图 |
| 无遗像 · 馆主 | 该格显示「上传遗像」引导，链到馆务管理 |

## 七、顺带修掉的一个真实缺陷

启用场景后，页面出现**两面几乎一样的墙**：顶部是绘制的壁龛场景，
下面的「3D 全景」兜底图 `public/assets/hall-cover.jpg` —— 恰好也是一张
**壁龛纪念墙的照片**。上下并排非常荒唐。

**修复**：壁龛模式下，只有馆主真的上传了 `coverImage` 才显示全景；
未上传时直接不渲染该区块。并补了回归断言（`hall-cover.jpg` 出现次数必须为 0）。

### 三档断点实测（最关键）

遗像与壁龛格是两套 DOM，因此**必须实测矩形包含关系**，不能只断言 HTML 字符串：

| 视口 | 遗像矩形 | 目标格矩形 | 结果 |
|---|---|---|---|
| 桌面 1440 | `[711,124] 34×24` | `[702,117] 53×37` | ⊆ ✅ |
| 平板 768 | `[377,110] 26×18` | `[370,105] 41×29` | ⊆ ✅ |
| 手机 375 | `[184,90] 15×10` | `[180,87] 23×16` | ⊆ ✅ |

三档的坐标系盒子比例均为 `1.714`（= 1200/700），遗像横向居中
（格心 x 与像心 x 误差 ≤1px）。

## 十、刻意留下的设计（勿"修复"）

- **遗像内缩 18%**：让木框露出来。看起来"没占满格子"是**有意**的。
- **无遗像时格子留白**：不画占位图、不画破图，与其它 44 个空格保持一致。
- **场景限高**：桌面不超过 420px。宁可两侧留白，也不让正文被顶到折叠线以下。
- **`nicheCell` 的 inset 上限 0.4**：防止脏数据把小图缩成一个点。
